# ISO 9000 Quality Management — GlucoGuide

This document establishes a **Quality Management System (QMS)** for GlucoGuide aligned with the **ISO 9000 family**:

| Standard | Role here |
|----------|-----------|
| **ISO 9000** | Fundamentals, vocabulary, and the seven quality management principles |
| **ISO 9001:2015** | Requirements we implement as process controls (not a claim of formal certification unless audited by an accredited body) |

> **Scope:** Product engineering, clinic operations tooling, WhatsApp messaging, and release of `frontend/`, `backend/`, `apps/mobile`, and `apps/provider`.  
> **Out of scope of this QMS doc:** Clinical diagnosis/treatment protocols (those remain with licensed clinicians). GlucoGuide only manages appointments, directory, subscriptions, and messaging.

## 1. Quality policy (ISO 9001 §5.2)

**GlucoGuide Quality Policy**

We provide reliable clinic booking and patient–clinic communication software. We commit to:

1. **Meeting requirements** — functional, security, privacy, and Meta WhatsApp rules for every release that touches those surfaces.
2. **Customer focus** — clinics and patients can book, confirm, and manage visits with minimal friction and clear error states.
3. **Risk-based thinking** — prevent account bans, data leaks, wrong-tenant access, and broken booking math before ship.
4. **Continual improvement** — every production defect becomes a recorded nonconformity with corrective action.
5. **Evidence** — releases are verified against written acceptance criteria (not “looks fine”).

Leadership (product owner / tech lead) reviews this policy when objectives or major product scope change.

## 4. Process map (process approach)

```text
[Plan] PRD / decisions.md / risk
   ↓
[Design & build] frontend + backend + Expo
   ↓
[Verify] typecheck + smoke + acceptance checklist
   ↓
[Release] migrate / seed / config
   ↓
[Operate] bookings, WhatsApp, billing webhooks
```

## 7. Operational controls (ISO 9001 §8) — implemented rules

### 7.1 Design & development

- Prefer changing the **canonical** stack: `backend/` + `frontend/` + Expo apps; do not invent a second booking engine.
- Document material design changes in `decisions.md`.
- WhatsApp copy/templates must remain **UTILITY** and match `whatsapp.metaTemplates.ts`.

### 7.2 Control of changes

Before merging changes that touch auth, booking, multi-tenant data, or WhatsApp:

1. Identify risk (see risk register).  
2. Update docs if behaviour changes.  
3. Run verification (typecheck + relevant smoke).  
4. Complete release checklist items that apply.

### 7.3 Customer communication & support

- Patients: clear booking confirmation / cancel / reschedule.  
- Clinics: queue actions without forced navigation.  
- WhatsApp: AI disclosure, HUMAN, STOP/START.

### 7.4 Externally provided processes

| Provider | Control |
|----------|---------|
| Meta Cloud API / BSP | Whatsapp-Meta-Rules; template APPROVED before LIVE |
| Razorpay | Webhook signature / simulate only in ops |
| LLM (HF / etc.) | No clinical advice; guardrails in `whatsapp.policy.ts` |
| Redis / Postgres | Migrations reviewed; Redis optional must not corrupt booking correctness |

### 7.5 Identification & traceability

- Bookings: UUID + practiceId + channel.  
- Notifications: `notificationEvent` with template key + send status.  
- Releases: git commit / tag noted on checklist.

## 9. Improvement — nonconformity & CAPA (ISO 9001 §10)

**Nonconformity (NC):** any failure to meet a requirement (bug that ships, Meta restriction, wrong-tenant leak, skipped go-live gate).

**Corrective action (CA):** remove the *cause*, not only the symptom.

Process:

1. Log in `documentation/qms/records/capa-log.md` (severity, severity, evidence).  
2. Contain (feature flag, pause LIVE number, revert).  
3. Root cause (5 Whys — brief).  
4. Corrective action + owner + due date.  
5. Verify effectiveness (retest).  
6. Update QMS docs / Cursor rules if the failure mode is new.

Severity:

| Sev | Meaning | Example |
|-----|---------|---------|
| 1 | Safety / ban / data breach / booking corruption | Cross-practice PII; Meta account ban |
| 2 | Major feature broken for many users | Login down; queue cannot complete |
| 3 | Limited / cosmetic | UI copy; single clinic edge case |
